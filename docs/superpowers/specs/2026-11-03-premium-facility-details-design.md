# 광고 시설 상세 정보 설계

## 목적

유료 광고(상단 노출) 사업자에게 눈에 보이는 혜택을 추가한다. 어르신 가족은 방문하기 전에 방 구조, 크기, 위치, 내부, 가격을 앱에서 미리 확인하고, 주변의 다른 광고 시설을 항목별로 살펴볼 수 있다.

현재 광고 혜택은 검색 상단 노출과 "광고" 배지뿐이다.

## 목표

- 광고 중인 시설의 상세 화면에 도면도, 방 크기, 네이버 지도 위치, 시설 둘러보기, 월세·전세·매매별 가격을 보여 준다.
- 사업자가 앱의 내 시설 관리에서 이 정보를 직접 등록하고 수정한다.
- 상세 화면의 버튼으로 주변 다른 광고 시설을 항목별로 본다.
- 둘러보기에서 거리뷰처럼 옆방으로 넘어간다.

## 하지 않는 것

- 두 시설을 나란히 놓는 비교 화면 (사용자가 항목별 목록을 선택함)
- 사진 속 특정 위치에 화살표를 찍는 편집기
- 공공데이터 시설이나 광고하지 않는 시설에 이 정보를 노출하는 것
- 서버 배포 (사용자가 요청할 때 별도로 진행)
- 광고 요금 변경

## 실패로 보는 경우

- 광고가 끝났는데 추가 정보가 계속 보이거나, 다시 광고했는데 등록 내용이 사라진 경우
- 다른 사업자의 시설 정보를 수정하거나 올릴 수 있는 경우
- 등록하지 않은 항목이 빈 칸이나 오류로 보이는 경우
- 일반 시설과 공공데이터 시설의 기존 화면이 달라지는 경우

## 사용자 화면

시안: 시설 상세 위쪽, 아래쪽, 주변 건물 항목별 보기의 세 화면. 사용자가 항목별 보기를 시안대로 승인했다.

### 시설 상세 (`src/app/facilities/[id].tsx`)

광고가 유효한 시설에서만 기존 화면에 다음 순서로 추가한다.

1. **도면도:** 사진은 앱 안에서 크게 본다. PDF는 눌렀을 때 휴대폰의 PDF 뷰어로 연다.
2. **방 크기:** 방 종류와 면적. ㎡와 평을 함께 표시한다.
3. **위치:** 네이버 지도에 시설 위치를 표시한다.
4. **시설 둘러보기:** 360° 사진을 끌어서 둘러보고, 화면 아래 이동 버튼으로 옆방에 간다.
5. **가격:** 월세, 전세, 매매 탭. 가격은 방 종류별로 받는다. 탭마다 방 종류별로 월세는 보증금과 월세, 전세는 보증금, 매매는 매매가를 보여 준다.
6. **주변 300~500m 다른 건물 보기** 버튼.

기존 예약, 상담 버튼은 그대로 둔다.

### 미등록과 빈 상태

- 도면도 또는 둘러보기를 등록하지 않은 광고 시설에는 해당 위치에 정확히 **"등록한 내용이 없습니다."** 를 표시한다.
- 등록하지 않은 방 종류, 방 크기, 가격에도 같은 문구를 표시한다. 어떤 방의 특정 거래 유형 가격이 없으면 그 방 줄에 표시한다.
- 주변 건물 화면의 탭에서 시설별 항목이 비어 있어도 같은 문구를 쓴다. (설계자 판단)
- 주변에 다른 광고 시설이 없으면 "주변에 다른 건물이 없습니다."를 표시한다. (설계자 판단)
- 시설 좌표가 없으면 지도 대신 주소 글자만 보여 주고, 주변 건물 버튼은 숨긴다. (설계자 판단)

### 주변 건물 보기 (새 화면)

- 기준 시설에서 반경 500m 안의 다른 광고 시설을 가까운 순서로 보여 준다. (설계자 판단: 요청한 300~500m를 500m로 정함)
- 탭은 도면도, 방 크기, 위치, 둘러보기, 가격이다. 탭을 바꾸면 같은 시설들의 해당 항목만 보인다.
- 가격 탭에는 월세, 전세, 매매 선택이 있다.
- 각 시설에 이름과 거리를 표시하고, 누르면 그 시설 상세로 이동한다.
- 로그인 없이 볼 수 있다. 기존 시설 조회와 같다.

### 사업자 등록 (`src/app/business/[id].tsx`)

내 시설 편집 화면에 다음을 추가한다.

- 도면도 업로드, 교체, 삭제 (사진 또는 PDF)
- 방 종류와 면적 추가, 수정, 삭제 (면적은 비워 둘 수 있음)
- 방 종류마다 거래 유형별 가격 입력
- 방마다 이름과 360° 사진 등록, 그 방에서 갈 수 있는 방을 목록에서 선택
- 광고 중이 아닐 때도 미리 등록할 수 있다. 등록한 내용은 광고 중일 때만 공개된다. (설계자 판단)

## 규칙

- **공개 조건:** 시설이 ACTIVE이고 구독 기간이 유효할 때. 기존 `current_period_end > NOW()` 기준을 그대로 쓴다.
- **광고 종료:** 앱에서 숨기기만 하고 지우지 않는다. 다시 광고하면 그대로 보인다.
- **방 연결:** 양방향으로 저장한다. A에서 B로 연결하면 B에서도 A로 갈 수 있다. (설계자 판단)
- **시작 방:** 등록 순서가 가장 빠른 방에서 시작한다. (설계자 판단)
- **권한:** 등록 API는 기존 `/api/business/**`의 소유권 범위를 따른다. 다른 사업자의 시설은 기존과 같이 404로 응답한다.
- **공개 API:** 광고가 유효하지 않으면 추가 정보를 응답에 넣지 않는다. 앱에서 숨기는 것으로 끝내지 않는다.
- **공공데이터 시설:** 사업자가 없으므로 이 기능의 대상이 아니다.

## 파일 규칙

- 도면도: JPEG, PNG, PDF. 최대 20MB. (설계자 판단)
- 360° 사진: JPEG. 최대 20MB. 가로:세로 2:1 비율만 허용해 일반 사진 등록을 막는다. (설계자 판단)
- 파일 내용으로 형식을 검증한다. 확장자만 믿지 않는다.
- 현재 업로드 제한은 5MB(`max-file-size`), 요청 6MB이므로 함께 올린다.
- 기존 일반 사진의 5MB 제한은 유지한다.
- 저장은 현재처럼 서버의 `uploads` 폴더를 쓴다. 서버 배포 때 저장 공간을 다시 검토한다.

## 위치와 거리

- 시설에 위도, 경도를 저장한다.
- 네이버 지오코딩 API로 주소를 좌표로 바꾼다. 광고를 시작할 때, 그리고 광고 시설의 주소가 바뀔 때 변환한다. 변환 실패는 광고 결제나 저장을 막지 않는다.
- 이미 광고 중인 시설은 배포할 때 한 번 변환한다.
- 거리는 저장된 좌표로 서버에서 계산한다.
- 네이버 API 키는 환경변수로 관리하고 저장소에 넣지 않는다.

## 만드는 순서

각 단계가 끝나면 사용자가 확인할 수 있어야 한다.

1. **입력 항목과 도면도:** 방 크기, 가격, 도면도 등록과 표시, 광고 조건, 미등록 문구
2. **지도와 주변 건물:** 좌표 저장, 네이버 지도, 주변 건물 항목별 화면
3. **시설 둘러보기:** 360° 보기, 방 등록과 연결, 옆방 이동

3단계를 시작하기 전에 실제 Android와 iOS 기기에서 360° 보기를 시험한다. 끌어서 돌리는 동작이 부드럽지 않으면 개발을 진행하기 전에 사용자와 상의한다.

## 제약

- 앱: Expo SDK 58, React Native 0.88, Expo Router. Expo API는 해당 버전 문서를 확인하고, 패키지는 `npx expo install`로 추가한다.
- 네이티브 코드가 있는 패키지를 추가하면 새 APK 빌드가 필요하다.
- 백엔드: Spring Boot, MyBatis, MySQL. 테이블은 `schema.sql`로 만든다.
- 화면 문구와 코드 주석은 한국어로 쓴다.
- 새 호출은 `apiFetch`와 `apiUpload`를 쓴다.
- 백엔드 소유권 격리와 공개 조건에는 자동 테스트를 둔다.

## 미리 필요한 것

- 사용자가 네이버 클라우드 플랫폼에서 지도와 지오코딩 API 키를 발급한다. 2단계를 시작하기 전까지 필요하다.
- 3단계 시험과 등록 확인을 위한 360° 사진 샘플.

## 검토 후 정한 부분 (설계자 판단)

- **지원 플랫폼:** Android와 iOS 모두 지원한다. (사용자 결정) 웹은 오류 없이 동작해야 하며 지도와 둘러보기는 대체 표시를 해도 된다.
- **주변 건물의 위치 탭:** 시설마다 주소와 거리를 글자로 보여 주고, 누르면 네이버 지도를 연다. 목록에 지도를 여러 개 띄우지 않는다.
- **주변 건물의 둘러보기 탭:** 시설마다 대표 사진과 방 개수를 보여 주고, 누르면 해당 시설의 둘러보기를 연다. 목록에 360° 뷰어를 여러 개 띄우지 않는다.
- **파일 공개 범위:** 광고가 끝나면 API 응답에서 뺀다. 추측하기 어려운 파일 주소를 쓰지만, 주소를 이미 아는 사람은 파일을 열 수 있다.

## 개발자에게 맡기는 것

- 테이블과 API의 세부 형태
- 360° 뷰어와 네이버 지도를 앱에 넣는 방식
- 파일 선택과 PDF 열기에 쓸 Expo 모듈 (AGENTS.md 기준으로 Expo 모듈 우선)
- 업로드 진행 표시 등 세부 화면 처리
